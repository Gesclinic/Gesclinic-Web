13 TIPOS DE AÇÕES AUDITADAS:
  • APPOINTMENT_CREATED         (Agendamento criado)
  • STATUS_CHANGED             (Status alterado)
  • CHECKIN_STARTED            (Check-in iniciado)
  • CHECKLIST_UPDATED          (Checklist atualizado)
  • FINANCIAL_VALIDATED        (Financeiro validado)
  • MERGE_PRE_PATIENT          (Pré-paciente linkado)
  • PATIENT_LINKED             (Paciente linkado)
  • PATIENT_CREATED            (Paciente criado)
  • ATTENDANCE_STARTED         (Atendimento iniciado)
  • ATTENDANCE_FINISHED        (Atendimento finalizado)
  • MARKED_NO_SHOW            (Falta marcada)
  • RESCHEDULED               (Remarcado)
  • CANCELLED                 (Cancelado)

DADOS CAPTURADOS POR LOG:
  • ID (UUID)
  • appointment_id (UUID)
  • action_type (tipo de ação)
  • old_status (status anterior)
  • new_status (novo status)
  • performed_by (user UUID)
  • performed_by_role (role do usuário)
  • performed_at (timestamp UTC)
  • context (dados estruturados em JSONB)
  • ip_address (IP da requisição)
  • user_agent (navegador do usuário)
  • created_at (quando foi logado)

================================================================================
                        TROUBLESHOOTING
================================================================================

ERRO: "relation 'appointment_audit_logs' does not exist"
  ❌ Migration não foi aplicada
  ✅ Execute a migration no Supabase Dashboard

ERRO: "permission denied for schema public"
  ❌ Problema de RLS
  ✅ Verifique se RLS foi aplicado corretamente

HISTÓRICO NÃO APARECE:
  ❌ Logs não foram inseridos ou role está errada
  ✅ Verifique console do navegador (F12)
  ✅ Procure por "[AUDIT]" nos logs

IP APARECE COMO NULL:
  ❌ API ipify falhou
  ✅ Normal - é melhor esforço
  ✅ User-Agent sempre é capturado

PERMISSÃO BLOQUEADA MESMO SENDO ADMIN:
  ❌ Role não está correto
  ✅ Verifique Supabase > auth > users > user_roles
  ✅ Verifique se role_name = "admin" ou "gestor"
