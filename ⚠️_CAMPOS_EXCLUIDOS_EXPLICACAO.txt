💡 POR QUE ELES NÃO FORAM CRIADOS?

┌─ services_allowed
│  └─ Deveria ser uma tabela M:M (muitos-para-muitos)
│     Cada sala pode ter MÚLTIPLOS serviços
│     Não cabe em uma coluna VARCHAR

├─ resources
│  └─ Deveria ser uma tabela M:M
│     Cada sala pode ter MÚLTIPLOS recursos
│     Com quantidade, descrição, etc
│     Não cabe em uma coluna JSON simples

├─ location
│  └─ Redundante! Já existe como "unit"
│     Por que ter duas colunas pro mesmo dado?

└─ status
   └─ Já existe como "is_active" (boolean)
      Simples: ativo ou inativo
      Se precisar mais, evolua para M:M depois

✅ SOLUÇÃO CORRETA:

Se você PRECISA desses dados, crie tabelas separadas:

┌─ room_services (M:M)
│  ├── id
│  ├── room_id (FK → rooms)
│  └── service_id (FK → services)

└─ room_resources (M:M)
   ├── id
   ├── room_id (FK → rooms)
   ├── resource_name
   └── quantity
