Depois que a migration executou com sucesso, faça estas validações:

VALIDAÇÃO 1: Coluna foi criada?
─────────────────────────────────

1. No Supabase SQL Editor, clique em "New query"

2. Cole esta query:

   SELECT column_name, data_type 
   FROM information_schema.columns 
   WHERE table_name = 'appointments' 
   AND column_name = 'official_status';

3. Clique em Run

4. Resultado esperado:
   ✅ Uma linha com:
      - column_name: official_status
      - data_type: appointment_official_status

   ❌ Se não aparecer nada, algo deu errado

─────────────────────────────────────────────────────────────────────────────

VALIDAÇÃO 2: Dados foram inicializados?
─────────────────────────────────────────

1. Copie esta query:

   SELECT official_status, COUNT(*) as total
   FROM appointments 
   GROUP BY official_status 
   ORDER BY total DESC;

2. Cole e execute

3. Resultado esperado:
   ✅ Você vai ver uma linha com:
      - official_status: scheduled
      - total: (número de agendamentos)

   ❌ Se disser "table does not exist" ou erro, a migration falhou

─────────────────────────────────────────────────────────────────────────────

VALIDAÇÃO 3: Índices foram criados?
────────────────────────────────────

1. Copie esta query:

   SELECT indexname 
   FROM pg_indexes 
   WHERE tablename = 'appointments' 
   AND indexname LIKE '%status%';

2. Execute

3. Resultado esperado:
   ✅ Você vai ver 3 índices:
      - idx_appointments_official_status
      - idx_appointments_clinic_status
      - idx_appointments_date_status

ERRO 1: "type 'appointment_official_status' already exists"
───────────────────────────────────────────────────────────

O que significa:
  → Você já executou a migration antes
  → O tipo ENUM já existe

O que fazer:
  ✅ Pode ignorar este erro!
  ✅ Significa que não precisa criar de novo
  ✅ Tudo está funcionando

Próximo passo:
  → Execute as validações acima
  → Se aparecerem os dados, está tudo bem!

─────────────────────────────────────────────────────────────────────────────

ERRO 2: "column 'official_status' already exists"
──────────────────────────────────────────────────

O que significa:
  → A coluna já foi criada antes
  → Você pode estar executando a migration novamente

O que fazer:
  ✅ Pode ignorar este erro também!
  ✅ A coluna já existe, é normal

Próximo passo:
  → Execute as validações acima
  → Verifique que os dados estão lá

─────────────────────────────────────────────────────────────────────────────

ERRO 3: "column 'clinic_id' does not exist"
────────────────────────────────────────────

O que significa:
  → Sua tabela appointments não tem a coluna clinic_id

O que fazer:
  1. Vá para a SQL_EXECUTE_SIMPLIFIED.sql
  2. Encontre a linha que menciona clinic_id
  3. Você pode:
     a) Remover a linha com clinic_id se a coluna não existir
     b) Substituir por outra coluna que existe (se houver)
  4. Execute novamente

─────────────────────────────────────────────────────────────────────────────

ERRO 4: "table 'appointments' does not exist"
──────────────────────────────────────────────

O que significa:
  → Sua tabela de agendamentos tem outro nome

O que fazer:
  1. Verifique o nome correto da tabela:
     SELECT table_name FROM information_schema.tables 
     WHERE table_schema = 'public';
  
  2. Edite o arquivo SQL_EXECUTE_SIMPLIFIED.sql
  3. Substitua "appointments" pelo nome correto em todas as linhas
  4. Execute novamente
