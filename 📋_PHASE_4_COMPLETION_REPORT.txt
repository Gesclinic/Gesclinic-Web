FUNCTIONS CREATED:
─────────────────────────────────────────────────────────────────────────────────

1. log_appointment_change()
   Type: TRIGGER FUNCTION
   Called: After INSERT | UPDATE | DELETE on appointments table
   Purpose: Automatically log all changes to audit_log table
   
   Features:
     ✅ Records operation type (CREATE/UPDATE/DELETE)
     ✅ Captures before/after snapshots as JSONB
     ✅ Identifies only changed fields for UPDATE operations
     ✅ Records timestamp and user ID from auth.uid()
     ✅ Triggers update_audit_summary() for statistics
   
   Key Logic:
     - INSERT → operation='CREATE', before=NULL, after=new_data
     - UPDATE → operation='UPDATE', before=old_data, after=new_data, changed_fields=diff
     - DELETE → operation='DELETE', before=old_data, after=NULL
   
   Returns: TRIGGER (COALESCE(NEW, OLD))

2. update_audit_summary()
   Type: PL/pgSQL FUNCTION
   Called: By log_appointment_change() trigger
   Purpose: Update daily statistics
   
   Features:
     ✅ Upsert pattern - creates row if not exists, updates if exists
     ✅ Counts incremented by operation type
     ✅ Tracks earliest/latest change times
     ✅ Updates updated_at timestamp
   
   Parameters:
     - p_clinic_id (UUID)
     - p_operation (VARCHAR) - CREATE | UPDATE | DELETE
   
   Returns: VOID

3. get_appointment_audit_history()
   Type: PL/pgSQL FUNCTION (SELECT)
   Called: By API to retrieve change history
   Purpose: Query complete change history for specific appointment
   
   Signature:
     get_appointment_audit_history(
       p_appointment_id UUID,
       p_limit INT DEFAULT 100
     )
   
   Returns: TABLE with columns:
     - operation (VARCHAR)
     - changed_at (TIMESTAMP)
     - changed_by (UUID)
     - changed_fields (TEXT[])
     - before_snapshot (JSONB)
     - after_snapshot (JSONB)
   
   Sorting: DESC by changed_at (most recent first)

4. get_audit_summary_for_clinic()
   Type: PL/pgSQL FUNCTION (SELECT)
   Called: By API for dashboard statistics
   Purpose: Query daily statistics for clinic
   
   Signature:
     get_audit_summary_for_clinic(
       p_clinic_id UUID,
       p_from_date DATE DEFAULT CURRENT_DATE - INTERVAL '30 days',
       p_to_date DATE DEFAULT CURRENT_DATE
     )
   
   Returns: TABLE with columns:
     - summary_date (DATE)
     - creates_count (INT)
     - updates_count (INT)
     - deletes_count (INT)
     - total_changes (INT)

HOOK 1: useRealtimeAppointmentChanges
─────────────────────────────────────────────────────────────────────────────────

Signature:
  useRealtimeAppointmentChanges(
    clinicId: string,
    appointmentId?: string | null,
    onChangeCallback?: (event: RealtimeChangeEvent) => void,
    debounceMs: number = 500
  )

Features:
  ✅ Subscribes to Supabase realtime changes
  ✅ Cross-tab synchronization via BroadcastChannel API
  ✅ Debounced updates to prevent UI thrashing (default 500ms)
  ✅ Automatic cleanup on unmount
  ✅ Returns {isSubscribed, lastUpdate}

Multi-Tab Communication:
  ✅ Creates BroadcastChannel: `appointment-changes:{clinicId}`
  ✅ Receives messages from other tabs (onmessage handler)
  ✅ Broadcasts own changes to siblings (postMessage)
  ✅ Gracefully falls back if BroadcastChannel not supported

Debouncing Logic:
  ✅ Each appointment gets independent debounce timer
  ✅ Multiple changes to same appointment consolidated
  ✅ Prevents duplicate UI refreshes
  ✅ Timers automatically cleaned up on unmount

Returns: {
  isSubscribed: boolean,
  lastUpdate: Record<string, number>  // timestamp by appointment_id
}
