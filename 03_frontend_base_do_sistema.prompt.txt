Atualize as telas da Base do Sistema para refletir
o modelo de dados oficial do Gesclinic Web.

═════════════════════════════════════════════════════════════════════════════════

REGRAS OBRIGATÓRIAS:

1. PROFISSIONAIS:
   ┌─────────────────────────────────────────────────────────────────────────┐
   │ - Abas: Dados | Serviços | Convênios | Agenda | Financeiro             │
   │ - Não permitir exclusão física (apenas inativar)                        │
   │ - Aba "Dados": nome, email, CPF, especialidade, telefone, activo       │
   │ - Aba "Serviços": listar serviços que o prof oferece (M:M)             │
   │ - Aba "Convênios": listar convênios que atende (M:M)                   │
   │ - Aba "Agenda": horários de trabalho por dia da semana                 │
   │ - Aba "Financeiro": regras de remuneração, comissão, etc               │
   └─────────────────────────────────────────────────────────────────────────┘

2. SERVIÇOS:
   ┌─────────────────────────────────────────────────────────────────────────┐
   │ Campos obrigatórios:                                                    │
   │ - Nome do serviço                                                       │
   │ - Descrição                                                             │
   │ - Tempo padrão (em minutos)                                             │
   │ - Tipo de cobrança (por consulta, por hora, por sessão, etc)          │
   │ - Permite encaixe (SIM/NÃO)                                             │
   │ - Exige autorização (SIM/NÃO)                                           │
   │ - Valor base (padrão para todos os convênios)                          │
   │ - Ativo (SIM/NÃO)                                                       │
   └─────────────────────────────────────────────────────────────────────────┘

3. CONVÊNIOS:
   ┌─────────────────────────────────────────────────────────────────────────┐
   │ - Código único                                                          │
   │ - Nome                                                                  │
   │ - Serviços cobertos (listar todos os serviços, marcar quais atende)    │
   │ - Valores por serviço (table: serviço | valor deste convênio)          │
   │ - Regras específicas (% desconto, margem mínima, etc)                  │
   │ - Contato (telefone, email)                                             │
   │ - Ativo (SIM/NÃO)                                                       │
   └─────────────────────────────────────────────────────────────────────────┘

4. SALAS:
   ┌─────────────────────────────────────────────────────────────────────────┐
   │ - Nome                                                                  │
   │ - Número/Identificação                                                  │
   │ - Capacidade (número de pessoas)                                        │
   │ - Serviços permitidos (listar todos, marcar quais podem ser feitos)    │
   │ - Recursos disponíveis (table: recurso | quantidade)                    │
   │ - Status (disponível, manutenção, indisponível)                         │
   │ - Ativo (SIM/NÃO)                                                       │
   └─────────────────────────────────────────────────────────────────────────┘

5. SELECTS DINÂMICOS:
   ┌─────────────────────────────────────────────────────────────────────────┐
   │ Todos os selects devem ser:                                             │
   │ - Dinâmicos (carregar dados da API, não hardcoded)                     │
   │ - Dependentes das regras já cadastradas                                │
   │ - Filtrados por clínica (clinic_id)                                    │
   │ - Com suporte a busca/filtro quando houver muitos items                │
   │ - Com opção de "Nenhum" / "Não aplicável" quando apropriado            │
   └─────────────────────────────────────────────────────────────────────────┘

═════════════════════════════════════════════════════════════════════════════════

OBJETIVO GERAL:

Garantir UX clara, sem quebra de fluxo e sem inconsistência.

✅ Componentes devem refletir 100% do modelo de dados oficial
✅ Validações devem ser intuitivas e informativas
✅ Fluxos de criação/edição devem ser lógicos
✅ Não permitir estado inconsistente do banco
✅ Design responsivo e acessível
